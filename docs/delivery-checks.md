# Delivery checks and project boundary

This is the static TourOps marketing site, with inline CSS/JavaScript and image assets. Existing `CLAUDE.md` identifies `touropsai.com` and preserves website-only scope; operational/AI build artifacts belong in their canonical repositories.

The `delivery-checks` candidate verifies tracked local resources, same-page fragment targets and inline/external JavaScript syntax without executing the app or contacting providers. Require it only after a green hosted baseline. For changed navigation, layout or lead-generation behavior, add a focused browser check; syntax and resource integrity do not prove those flows.

The inspected Vercel team has two projects linked to this repository's `main`: `tourops-landing` (`prj_XMZFSI6Q8NXkhZrXuQS4uqQFD2EI`) and `tourops-landing-32yk` (`prj_XSWSflb5GS6bYcpc0qm4kKzUqTgZ`). Preserve both connections. Verify actual provider project, commit and authoritative domain when a release changes the product; a project name is not domain evidence. This governance adoption does not authorize retiring, relinking or reviving a separate site.

Follow [SOFTWARE_DELIVERY.md](../SOFTWARE_DELIVERY.md) and the adapted skill for proportional brainstorming, planning, independent final-diff review and authorized delivery.
